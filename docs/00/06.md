Let’s dive deep into **Experiment with Model Structure**. This category focuses on altering the fundamental architecture of your simulation—the rules that govern space, movement, and agent interactions. Changing the model structure can reveal new emergent behaviors and help you test ecological theories. Below are several concrete ways to restructure your model, with explanations and implementation hints.

---

## 1. Change the Grid Topology

Your current grid is a torus (wrap‑around), which eliminates boundaries and makes the world homogeneous. Try these alternatives:

### a. Bounded Grid with Reflecting Boundaries
Set `torus=False` when creating the grid. Then rabbits cannot move off the edge. This creates edge effects: rabbits near the border have fewer neighbors, and grass near edges might be less accessible. To implement:
- In `Rabbit.step()`, when choosing a new position, filter out moves that go outside the grid.
- Alternatively, let rabbits attempt to move but stay put if the move is invalid.

**Why?** Real ecosystems have boundaries (rivers, mountains, etc.). Edges often have different ecological dynamics (edge effects).

### b. Irregular or Heterogeneous Grid
Use a `NetworkGrid` instead of a `MultiGrid`. This connects cells in a graph (e.g., a Voronoi diagram, a random network, or a realistic landscape). Rabbits move along edges. This is great for representing fragmented habitats or river networks.

**Implementation hint**: You’d need to define the graph structure (nodes = cells, edges = connections). Mesa’s `NetworkGrid` works with a `networkx.Graph`. Place agents on nodes.

### c. Continuous Space (instead of grid)
Mesa also supports continuous space via `mesa.space.ContinuousSpace`. Agents have floating‑point coordinates and can move in any direction. This is more realistic for animal movement but requires collision detection or distance‑based interactions.

**Implementation hint**: Replace `MultiGrid` with `ContinuousSpace` (width, height, torus). Agents store `pos` as (x,y) floats. Movement becomes vector‑based. Eating grass would require checking distance to grass patches (which could also be continuous objects).

## 2. Modify Movement Rules

Your rabbits currently move one random step (Moore neighborhood) each turn. Experiment with:

### a. Directional Persistence (Correlated Random Walk)
Give rabbits a “direction” memory. They tend to continue in the same direction with some probability, simulating inertia. This creates more realistic movement patterns.

**Pseudo‑code**:
```python
def step(self):
    if not hasattr(self, 'last_direction'):
        self.last_direction = random.choice(possible_steps)
    # with probability p, keep same direction; else random
    if random.random() < self.persistence:
        new_pos = self.last_direction
    else:
        new_pos = random.choice(possible_steps)
    self.model.grid.move_agent(self, new_pos)
    self.last_direction = new_pos
```

### b. Movement Cost Based on Distance
If you use `ContinuousSpace`, let rabbits move a variable distance each step (related to `gene_speed`). Moving farther costs more energy. This makes speed an energetically costly trait, leading to trade‑offs.

### c. Foraging (Directed Movement Toward Grass)
If rabbits can sense grass within a certain radius, they can move toward the nearest grass. This introduces spatial memory and foraging efficiency.

**Implementation**: In `Rabbit.step()`, get all grass agents within vision range (using grid neighborhood or distance). If any exist, move toward the closest one (e.g., step in that direction). If not, move randomly.

### d. Obstacle Avoidance
Add obstacles (rocks, rivers) that rabbits cannot enter. You could mark certain cells as impassable. In movement, only consider neighboring cells that are not obstacles.

## 3. Introduce Agent Memory

Give rabbits a simple memory of recent locations or food sources.

### a. Return to Previously Productive Sites
Rabbits could remember cells where they found grass recently and bias movement toward those cells. Implement a `memory` list (e.g., last 5 successful eating locations). Weight movement choices by proximity to remembered spots.

### b. Avoid Overgrazed Areas
If grass takes time to regrow, rabbits might learn to avoid cells that are currently bare. They could remember which cells were bare recently and avoid them until regrowth is likely.

**Pseudo‑code**:
```python
def step(self):
    # update memory: store current cell if it had grass
    if self.just_ate:
        self.memory.append(self.pos)
        if len(self.memory) > 10: self.memory.pop(0)
    # when moving, prefer cells not in memory (if memory is of overgrazed spots)
    candidates = [pos for pos in possible_steps if pos not in self.memory]
    if not candidates: candidates = possible_steps
    new_pos = random.choice(candidates)
```

## 4. Add Social Structure

Rabbits are currently solitary. Introduce social behaviors:

### a. Herding / Flocking
Rabbits could tend to move toward other rabbits (cohesion) while avoiding crowding (separation). This creates group dynamics. Use rules similar to Craig Reynolds’ boids algorithm.

**Implementation**: In continuous space, each rabbit calculates a vector toward the center of nearby rabbits, a vector away from too‑close rabbits, and a vector matching neighbors’ headings. Combine and move.

### b. Territoriality
Rabbits could claim territory and defend it. For example, each rabbit has a home range. When another rabbit enters, there is a probability of conflict (energy loss) or expulsion.

### c. Communication
Add warning signals: when a predator is near (if you add predators), rabbits could emit a signal that alerts nearby rabbits, causing them to flee.

## 5. Introduce Temporal Structure (Time of Day / Seasons)

Model structure isn’t just spatial; it’s also temporal.

### a. Day/Night Cycle
Rabbits might be more active during the day (higher movement) and rest at night (lower metabolism). Grass could have different regrowth rates.

### b. Seasons
Add a global counter that cycles through seasons. In winter, grass regrowth stops or slows; rabbit metabolism increases to stay warm. This forces rabbits to store energy or die.

**Implementation**: In `EcosystemModel.step()`, increment a `season` counter and adjust parameters (e.g., `grass_regrowth_time`). Pass these to agents via model attributes.

## 6. Change Reproduction Mechanics

Your reproduction is asexual and triggered by energy threshold. Try:

### a. Sexual Reproduction
Introduce male/female rabbits. Reproduction requires a male and female to be on the same cell and both have enough energy. Offspring genes are a mix of both parents (with mutation). This adds mate‑finding dynamics and Allee effects.

**Implementation**: Add a `gender` attribute at birth. In `step()`, if energy above threshold, look for an opposite‑gender rabbit in the same cell. If found, both invest energy to create offspring (genes = average of parents + mutation).

### b. Reproduction with Mating Displays
Males could have a display trait (e.g., brighter color) that costs energy but increases mating success. Females choose males based on trait. This leads to sexual selection.

### c. Reproductive Suppression
In high population density, rabbits might delay reproduction (e.g., via stress hormones). Implement a density‑dependent reproduction probability.

## 7. Add Environmental Stochasticity

Model structure can include random events that reshape the environment.

### a. Fires
With some low probability, a fire sweeps through a region, killing all grass and possibly rabbits in that area. Grass regrowth starts from zero.

**Implementation**: In `model.step()`, if random() < fire_probability, select a random cell and set all grass in a radius to `grown=False` and countdown = regrowth_time. Optionally kill rabbits caught in fire.

### b. Floods / Droughts
Temporarily alter grass growth rates or rabbit metabolism over large areas.

### c. Disease Outbreaks
When rabbit population is high, a disease can appear and spread, killing a fraction of rabbits.

---

## 8. Implement Energy Flow Between Trophic Levels

If you add predators, you can also add decomposition.

### a. Decomposers
When rabbits die, their bodies could become nutrients that fertilize nearby grass, speeding regrowth. This closes the nutrient loop.

**Implementation**: In `Rabbit.remove()`, place a temporary “carcass” agent that decays over time, releasing nutrients to grass in the same cell (e.g., reduce grass regrowth time for a while).

## 9. Use Different Agent Activation Orders

Your current approach uses `agents_by_type[Grass].do("step")` and then `agents_by_type[Rabbit].shuffle_do("step")`. This is a simple form of staged activation. Mesa offers schedulers that can mix orders:

- **RandomActivation**: All agents (grass and rabbits) step in random order each tick. This could lead to grass regrowing after rabbits have eaten in the same step, which might be unrealistic but could be interesting.
- **SimultaneousActivation**: All agents calculate their next state based on the current state, then update together. This avoids order artifacts.

**Implementation**: Use `mesa.time.RandomActivation` and add both grass and rabbits to it. Then call `schedule.step()`.

## 10. Voxel / 3D Grid

If you’re feeling ambitious, extend to a 3D grid (e.g., height layers). This could model elevation or vertical stratification (e.g., rabbits on ground, birds above). Mesa’s `MultiGrid` is 2D, but you could create a custom 3D grid using dictionaries or a list of layers.

---

Each of these structural changes will alter the dynamics in nontrivial ways. Start with one that intrigues you, implement it, and observe how the system responds. You’ll gain insight into both ecological principles and the mechanics of agent‑based modeling.
