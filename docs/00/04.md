## 1. Use Mesa’s Built‑in Schedulers

Your current approach (`agents_by_type[Grass].do("step")` and `.shuffle_do("step")`) works, but Mesa provides dedicated scheduler classes that can make your code cleaner and more flexible.

**Example using `RandomActivation`** (agents step in random order each turn):

```python
from mesa.time import RandomActivation

class EcosystemModel(mesa.Model):
    def __init__(...):
        super().__init__(seed=seed)
        ...
        self.schedule = RandomActivation(self)
        # Add all agents to the scheduler
        for grass in self.agents_by_type[Grass]:
            self.schedule.add(grass)
        for rabbit in self.agents_by_type[Rabbit]:
            self.schedule.add(rabbit)

    def step(self):
        self.datacollector.collect(self)
        self.schedule.step()  # calls step() on all agents in random order
```

If you need grass to act *before* rabbits every step (e.g., regrow first), you can either use two separate schedulers or a custom step order:

```python
def step(self):
    self.datacollector.collect(self)
    # Grass first
    for agent in self.agents_by_type[Grass]:
        agent.step()
    # Then rabbits in random order
    self.agents_by_type[Rabbit].shuffle_do("step")
```

Using `RandomActivation` is still fine; the key is to be consistent and avoid manual iteration when the scheduler can handle it.

## 2. Optimize Grass Regrowth

Currently, every grass agent executes a `step()` even if it is already fully grown. For large grids (e.g., 500×500), this wastes CPU cycles. Instead, maintain a set of grass patches that are regrowing and only update those.

**Modify Grass class**:

```python
class Grass(mesa.Agent):
    def __init__(self, model):
        super().__init__(model)
        self.grown = True
        self.countdown = 0

    def step(self):
        # Only called for regrowing grass (see below)
        self.countdown -= 1
        if self.countdown <= 0:
            self.grown = True
            # Remove from regrowing set
            self.model.regrowing_grass.discard(self)

    def get_eaten(self):
        if self.grown:
            self.grown = False
            self.countdown = self.model.grass_regrowth_time
            # Add to regrowing set
            self.model.regrowing_grass.add(self)
            return True
        return False
```

**In the model**:

```python
class EcosystemModel(mesa.Model):
    def __init__(...):
        ...
        self.regrowing_grass = set()  # empty initially

    def step(self):
        # Only step through regrowing grass
        for grass in list(self.regrowing_grass):  # copy to avoid modification during iteration
            grass.step()
        # Then handle rabbits as before
        self.agents_by_type[Rabbit].shuffle_do("step")
        self.datacollector.collect(self)
```

This reduces the work from O(grid cells) to O(number of regrowing patches).

## 3. Efficient Agent–Cell Interactions

Your rabbit’s `step()` uses `get_cell_list_contents` and then filters with `isinstance`. Since you know each cell contains exactly one grass agent, you can avoid the overhead of scanning the whole list.

**Option A: Store a reference to the grass in each cell**  
You could create a parallel grid or dictionary mapping coordinates to the grass agent. However, this duplicates data and must be kept in sync.

**Option B: Use `grid.get_cell_list_contents` and assume the first grass is the one**  
Because you only place grass at initialization and never move it, the list will contain exactly one grass agent. You can do:

```python
cell_agents = self.model.grid.get_cell_list_contents([self.pos])
# The grass agent is the first (and only) non‑rabbit agent
grass = next((a for a in cell_agents if isinstance(a, Grass)), None)
if grass and grass.get_eaten():
    self.energy += self.model.energy_from_grass
```

This is still an `isinstance` check but avoids creating a new list comprehension. For even faster access, you could store a dictionary `self.cell_grass` that maps positions to grass agents:

```python
# In model.__init__, after placing grass:
self.cell_grass = {}
for cell in self.grid.coord_iter():
    agents = cell[1]  # the list of agents at that coordinate
    for a in agents:
        if isinstance(a, Grass):
            self.cell_grass[cell[0]] = a
            break
```

Then in rabbit step:

```python
grass = self.model.cell_grass.get(self.pos)
if grass and grass.get_eaten():
    self.energy += self.model.energy_from_grass
```

This is the fastest lookup, but requires maintaining the dictionary if grass ever moves (it doesn’t).

## 4. Reduce Agent Creation Overhead

In reproduction, you create a new `Rabbit` agent each time. If the population grows large, frequent creation can be costly. However, this is usually acceptable. A minor improvement is to avoid recalculating the same neighborhood multiple times per step (but your rabbit moves only once). You could also batch births/deaths at the end of the step to avoid mid‑step modifications that might interfere with iteration.

Mesa’s scheduler handles adding/removing agents safely if you use `self.schedule.add()` and `self.remove()`. Your current use of `self.remove()` inside the rabbit step is fine because you are iterating over a copy (due to `shuffle_do` which likely creates a list of agents before stepping). But if you switch to a scheduler, be aware that removing agents during iteration can cause issues. Mesa’s `RandomActivation` handles this by storing agents in a dict and iterating over a list of keys, so removal is safe.

## 5. Data Collection Performance

Your `DataCollector` uses a lambda that calls `self.agents_by_type[Rabbit].__len__()`. This is efficient because `agents_by_type` is a dictionary maintained by Mesa. However, if you add more complex reporters (e.g., average energy), ensure they are computed efficiently. Avoid heavy computations inside the lambda; compute values once per step and store them if needed.

Example of a more efficient reporter for average speed:

```python
def compute_avg_speed(model):
    rabbits = model.agents_by_type[Rabbit]
    if rabbits:
        return sum(r.gene_speed for r in rabbits) / len(rabbits)
    return 0

self.datacollector = mesa.DataCollector(
    model_reporters={
        "Population": lambda m: len(m.agents_by_type[Rabbit]),
        "Avg Speed": compute_avg_speed,
    }
)
```

## 6. Batch Running and Parameter Exploration

For systematic experiments, use Mesa’s `batch_run` (or `BatchRunner` for older versions). This allows you to run many parameter combinations efficiently. To prepare your model:

- Make sure all parameters are passed to `__init__` and stored as attributes.
- Use `model.random` for reproducibility; set the seed in batch runs.

Example batch run:

```python
from mesa.batchrunner import batch_run

params = {
    "width": 20,
    "height": 20,
    "initial_rabbits": [2, 5, 10],
    "grass_regrowth_time": [5, 10],
    "energy_from_grass": 5,
    "reproduction_threshold": 20,
    "seed": [42, 123]  # optional
}

results = batch_run(
    EcosystemModel,
    parameters=params,
    iterations=5,        # runs per parameter combination
    max_steps=100,
    data_collection_period=1,
    display_progress=True,
)
```

This runs simulations in parallel (if `multiprocessing` is available) and returns a list of dictionaries with all collected data.

## 7. General Python Optimizations

- **Use local variables inside loops**: In hot loops (e.g., grass regrowth), assign frequently used attributes to local variables.
- **Avoid attribute lookups**: For example, inside rabbit step, assign `self.model` to a local variable `model` if accessed many times.
- **Prefer `list` over `set` for small collections**: But for membership tests, `set` is faster.
- **Use `random` module efficiently**: Your model already uses `self.random` which is seeded and faster than `random` module directly.

Example of local variable optimization in rabbit step:

```python
def step(self):
    model = self.model
    # Move
    possible = model.grid.get_neighborhood(self.pos, moore=True, include_center=False)
    new_pos = model.random.choice(possible)

    # Eat
    grass = model.cell_grass.get(self.pos)   # if you added the dictionary
    if grass and grass.get_eaten():
        self.energy += model.energy_from_grass
    # Metabolism
    self.energy -= self.gene_metabolism
    # Reproduction...
```

## 8. Profiling and Testing

Before and after changes, profile your simulation to identify bottlenecks:

```python
import cProfile
cProfile.run('model = EcosystemModel(); for i in range(100): model.step()', 'stats')
```

Use tools like `snakeviz` to visualize the results. Focus on functions that consume the most time.

Additionally, write unit tests for critical logic (e.g., grass regrowth, rabbit energy changes) to ensure optimizations don’t break behavior.
